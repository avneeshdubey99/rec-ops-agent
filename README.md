# Rec Center Operations Agent (LangGraph)

A stateful AI agent for Texas A&M Rec Center operations. It **plans** multi-step analyses,
**calls tools** (SQL, forecasting, staffing), **recovers from failures** at six levels, and
**pauses for manager approval** before changing the shift schedule.

> **All data is fake**, generated by `data/generate_data.py`.

## What it can do
- Answer ad-hoc questions: *"Which facility had the most check-ins last week?"*
- Forecast traffic: *"How busy will Monday evening be?"*
- Find staffing gaps and draft shifts: *"Which hours next week are understaffed? Fix it."*
- Publish only the shifts a manager approves.

## Architecture
```
START -> planner -> executor -> evaluator --(retry with feedback / next step)--> executor
                        |           |
                        |           +--(step failed every attempt)--> replanner -> executor
                        |           |
                        |           +--(all steps done)--> synthesizer --(shifts drafted?)--> approval -> END
                        |                                       |                              (interrupt)
                        |                                       +--(no)--> END
                        v
              [subgraph] agent <-> tools
```

| Node | Job |
|---|---|
| `planner` | Breaks the question into 1-4 steps (structured output), using recent conversation for follow-ups |
| `executor` | A tool-calling subgraph that completes one step |
| `evaluator` | Grades the step result; accepts, retries with feedback, or triggers re-planning |
| `replanner` | Replaces a failed step with a different approach |
| `synthesizer` | Writes the final answer from all step results |
| `approval` | `interrupt()` pauses the graph until a manager approves or rejects the drafted shifts |

**Tools:** `run_sql` (read-only), `forecast_traffic`, `find_staffing_gaps`, `propose_shifts`, `get_schema`.
Forecasting and staffing math lives in plain Python (`agent/staffing.py`), not the LLM.

### Failure recovery, layer by layer
1. **Tool:** transient DB errors are retried with exponential backoff; other errors come back as text.
2. **Executor:** the LLM reads tool errors (like bad SQL) and fixes its own calls; a recursion limit stops endless loops.
3. **Evaluator:** weak or wrong results are rejected and retried with feedback (2 attempts per step).
4. **Replanner:** a step that keeps failing is replaced with a new approach (1 re-plan per question).
5. **Node:** `RetryPolicy` re-runs a node on API errors such as timeouts and rate limits.
6. **Graph:** a SQLite **checkpointer** saves state after every node, so a crashed or stopped run resumes where it left off.

Try it yourself with **chaos mode**, which randomly fails database calls: use the slider in the app, or run `python main.py --chaos 0.3`.

## Setup (Windows, Command Prompt)
```bat
cd %USERPROFILE%\Documents\rec-ops-agent
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
copy .env.example .env
notepad .env
python data\generate_data.py
```
Put your Anthropic API key (from console.anthropic.com) in `.env`. The default model is `claude-sonnet-5`; set `LLM_MODEL=claude-haiku-4-5-20251001` for the cheapest option. OpenAI also works: set `LLM_PROVIDER=openai`, add `OPENAI_API_KEY`, and `pip install langchain-openai`. Requires Python 3.10+.
(macOS/Linux: `source .venv/bin/activate`, `cp .env.example .env`.)

## Run
```bat
streamlit run app.py        :: web app: chat, live reasoning, approval table, staffing charts
python main.py              :: terminal version
python main.py --thread ID  :: continue or resume a saved conversation
python -m tests.test_graph  :: offline tests with a scripted fake LLM (no API key needed)
python -m agent.graph       :: print a Mermaid diagram (paste into mermaid.live)
```

### Demo script
1. Ask: **"Which hours next week will be understaffed? Propose shifts to fix it."**
   Watch the plan, the tool calls, the evaluator, then the approval table.
2. Untick a few shifts, then **Publish**. Check the *Staffing outlook* tab: the gaps shrink.
3. Follow up: **"What about the week after?"** The checkpointer remembers the context.
4. Set the failure slider to 0.5 and ask again to watch the retries and recovery.
5. Stop the CLI mid-run with Ctrl+C, then `python main.py --thread <id>` to resume from the checkpoint.

## Project layout
```
app.py              Streamlit UI
main.py             CLI
agent/graph.py      main graph: nodes, routing, retry policies, interrupt
agent/executor.py   tool-calling subgraph
agent/state.py      graph state + structured-output models
agent/tools.py      LLM-facing tools
agent/staffing.py   forecasting, gap detection, shift proposals, publishing
agent/db.py         DB access, transient-error retries, chaos mode
agent/memory.py     SQLite checkpointer
agent/runner.py     shared streaming/resume helpers for CLI + app
agent/llm.py        LLM setup (Claude by default, OpenAI optional)
data/               dummy data generator (+ generated DBs, git-ignored)
tests/              offline end-to-end tests
```

## Tests cover
Retry with evaluator feedback and SQL self-correction · re-planning after repeated failure ·
shift proposal, then interrupt, then partial approval written to the DB · transient DB retries ·
node `RetryPolicy` · crash, then resume from checkpoint.

## Staffing rule (dummy)
1 staff per 30 expected check-ins per hour, minimum 2, staffed 6:00-22:00, 4-hour shifts,
no double-booking, weekly hour limits respected. Forecast = average of the same weekday
and hour over the last 4 weeks.

## Resetting
Delete `data\rec_center.db` and `data\checkpoints.sqlite`, then run `python data\generate_data.py`.
Regenerate every couple of weeks, since the dummy schedule only extends 14 days past the day you generate it.
